Problem

Small shops in Jakarta invoiced customers over WhatsApp and chased payment by hand. Owners kept a notebook of who owed what, and an invoice took 13.1 days on average to get paid.

The goal was a tool a shop owner could learn in ten minutes: it sends a link the customer can pay from, and it reminds them politely without the owner doing anything.

My role

I built Ledgerly alone, from scoping with three shop owners to running it in production: the Next.js dashboard, the Go API, the PostgreSQL schema, the Midtrans payment integration, and the reminder worker. A designer helped for two weeks on the invoice and pay-link screens.

Approach

Four decisions shaped the product. Each one traded something away on purpose.

  • Pay links, not customer accounts

    Customers pay from a link with no sign-up. The link carries a signed token that expires with the invoice.

    Gave up: payment history for customers across shops.

  • Reminders as a job queue, not cron

    Each invoice schedules its own reminders in a Postgres job table read with SKIP LOCKED, so a crashed worker never sends the same reminder twice.

    Gave up: one more process to deploy and watch.

  • Money as whole rupiah

    Amounts are stored as integers, and Midtrans webhooks are applied idempotently by order id, so retries cannot double-count a payment.

    Gave up: support for currencies with cents, for now.

  • Server-rendered dashboard

    Pages render on the server with React Server Components and ship under 100 KB of JavaScript, which keeps the dashboard quick on the mid-range Android phones most owners use.

    Gave up: some offline behaviour a single-page app could have had.

Architecture

Two front doors, one API, and a worker that owns everything that happens later.

CustomerOpens the pay link
DashboardNext.js, server-rendered

PostgreSQLInvoices and job table

MidtransPayments, external
WhatsApp APIMessages, external
  • The shop owner creates invoices in the dashboard.
  • The dashboard calls the Go API.
  • The customer opens the pay link page.
  • The pay link page asks the API for a Midtrans payment.
  • The API stores invoices and schedules reminder jobs.
  • The API creates payments in Midtrans, and Midtrans calls back when a customer pays.
  • The worker claims due reminder jobs.
  • The worker sends reminders over WhatsApp.
