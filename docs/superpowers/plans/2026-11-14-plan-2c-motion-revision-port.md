# Plan 2c: Port the motion revision into the app

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the app match the owner-approved mockup revision of 2026-11-14 (commit `fba0ca3`). The changes:
- a hero background of punched dust that leans toward the mouse
- floating hero stickers that lean with the mouse
- a big hero statement with icon stickers inline, and icon stickers in the About sentence and the closing headline
- achievement passes that take turns between several photos
- no reel pause button: hover slows the reel instead of stopping it

**Architecture:** The mockup is the visual source of truth.
- `src/app/site.css` is a 1:1 port of `mockup/styles.css` as it stood at `12918e8`, so the home port replays the CSS diff `12918e8..fba0ca3` onto it.
- The behaviour in `mockup/main.js` (same range) moves into `src/components/home/home-motion.ts`, following its existing cleanup pattern.
- Owner copy gains two tiny, opt-in markups, so the owner keeps editing text in the editor:
  - `:name:` places an icon sticker, from a fixed list of eight Phosphor Bold icons.
  - ` / ` breaks a statement line.
- Achievements gain three more nullable photo columns (photo 2 to 4), edited with the existing single media picker.

**Tech Stack:** Next.js 16 (App Router, server components), React 19, Drizzle ORM + better-sqlite3, Vitest, Playwright, GSAP (already a dependency).

**Spec:** `docs/superpowers/specs/2026-11-14-portfolio-cv-design.md`.
- `DESIGN.md` records the visual system.
- Where the spec and the mockup disagree on looks, the mockup wins. On behaviour and data, the spec wins, except for the owner's decisions recorded in this plan:
  - the reel has no pause button
  - hover slows the reel instead of stopping it
  - Task 4 amends the spec to say so

**Interfaces:**
- Produces: in `@/lib/inline`, `ICON_STICKERS = ["browsers", "database", "cursor", "pin", "loading", "team", "rocket", "wave"] as const` and `type IconStickerName = (typeof ICON_STICKERS)[number]`.
- Produces: `parseInline(src: string, opts?: { icons?: boolean }): InlineSegment[]`, where `InlineSegment = { text: string; strong?: true; em?: true } | { icon: IconStickerName }`. Icon segments come back only when `opts.icons` is true.
- Produces: `toPlain(src: string): string` in `@/lib/inline`. It drops `**` and `_` markers and known `:name:` tokens, turns ` / ` into a single space, and collapses repeated spaces. It is the only way owner copy with markup may reach plain-text outputs.
- Produces: `statementLines(...lines: string[]): string[]` in `@/lib/statement`. It splits each line on ` / ` (a slash with a space on both sides), trims the parts and drops empty ones.
- Produces: `<IconSticker name rot? className? />`. It renders `<span className="ico-stk ..." style={{ "--r": `${rot}deg` }}><svg aria-hidden="true" viewBox="0 0 256 256"><path d=... /></svg></span>`, with the eight bold paths copied verbatim from the `i-b-*` symbols in `mockup/index.html`:
  - browsers: `i-b-browsers`
  - database: `i-b-database`
  - cursor: `i-b-cursor`
  - pin: `i-b-pin`
  - loading: `i-b-loading`
  - team: `i-b-team`
  - rocket: `i-b-rocket`
  - wave: `i-b-wave`
- Produces: `<Inline text icons? />`. When `icons` is true it renders icon segments as `<IconSticker>`, with rotations taken in turn from `[-7, 5, -4, 6, -5, 7]` (degrees).
- Produces: `SectionHead` gains an optional `after?: ReactNode`, rendered inside the `h2` after the title and a space.

    - Without `{ icons: true }` the same input comes back as plain text.
    - An unknown token (`:nope:`) stays plain text.
